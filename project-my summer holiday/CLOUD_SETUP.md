# ongoing_ 双账号内测：复制邀请，粘贴加入

本轮入口不依赖微信分享卡片。A 复制一段邀请文字，手动发给 B；B 用自己的微信打开同一份小程序体验版，在「生活 → 加入共同记录」粘贴。Chapter 与 Moment 共用入口，由云端邀请码决定加入范围。

## 先更新部署

1. 在微信开发者工具右键 `cloudfunctions/collaboration` → **上传并部署：云端安装依赖**，选择 `cloud1-d3gkyt79x24b49e66`。
2. 上传最新小程序并设为体验版。确保 A、B 都是此小程序的体验成员，并分别用自己的微信打开新版体验版；邀请码用于授予内容权限，不能替代微信后台的体验成员资格。

AppID 沿用 `project.config.json` 中的 `wxbda0de1c39652c2d`。用户已确认建好五个集合：`ongoing_users`、`ongoing_chapters`、`ongoing_moments`、`ongoing_contributions`、`ongoing_invites`。无需新增集合、清空缓存或迁移数据。

数据库五个集合由云函数读写，客户端不直连集合；可保持仅管理员读写。云存储需允许用户上传自己的文件，成员读取由云函数校验内容访问权后签发临时地址。已有权限配置本轮未在线读取或修改。

## Chapter：A 创建 → B 加入 → B 填写 → A 看见

| 操作 | 验收结果 |
| --- | --- |
| A 创建 Chapter，并在其中发布一条 Moment | 内容先在本机保存，上传成功后才能生成有效邀请 |
| A 点「邀请一起记录」 | 复制包含十二位邀请码的文字，无需打开微信分享面板 |
| A 把这段文字手动发给 B | 例如 `ABCD-EF12-3456`，也可以直接复制整段文字 |
| B 打开体验版 → 生活 → 加入共同记录 → 粘贴邀请信息 | 云端返回 Chapter 名称、邀请人、日期、封面、人数 |
| B 确认加入，可设置自己的昵称头像 | 进入同一个 Chapter；生活的 Chapter 列表自动包含它 |
| B 查看 A 已有 Moment，再在 Chapter 内新增自己的 Moment | 原作者显示 A，新 Moment 显示 B；图片、声音可查看 |
| A 重新进入该 Chapter，或下拉刷新 | 看到 B 新增的内容 |
| B 修改自己创建的 Moment；A 再次进入 / 下拉 | A 看到最新内容 |
| A、B 完全退出小程序后重进 | Chapter、成员和记录仍存在 |

建议 A、B 先在「我的」设置容易区分的昵称。不设置也会使用按真实账号生成的默认名称；头像和昵称不承担身份鉴别。

## 单个 Moment：B 留下并继续编辑自己的视角

建议用一条**不属于 Chapter** 的 Moment 单独测试，确认这条链路本身成立。

1. A 发布 Moment → 详情中的「邀请朋友留下视角」→「复制邀请信息」，把文字发给 B。
2. B 在「生活 → 加入共同记录」粘贴，确认加入后进入原 Moment。
3. B 点「留下我的视角」，填写文字 / 图片 / 语音并保存。
4. A 重新进入 Moment 或下拉刷新，详情分别显示原文和 B 的视角。
5. B 点「编辑我的内容」，修改后保存；A 刷新应看到更新后的 B 内容，A 原文不变。
6. B 退出重进，仍能从生活中的所有 Moment 找到这条记录，并继续编辑自己的视角。

单条邀请也可用于 Chapter 内的 Moment。它只授予这一条的访问与贡献权限，不自动加入整个 Chapter；要共同浏览整章，请使用 Chapter 邀请。

## 核实数据确实在云端

界面提示只是第一层确认，真机验收时还应查看当前云环境：

- `ongoing_users`：A、B 的 `id` 不同，来源于云函数的真实 OPENID。
- `ongoing_chapters`：同一 Chapter 的 `memberIds` 同时包含 A、B，重复加入不会增加重复成员。
- `ongoing_moments`：A、B 创建的记录具有不同 `creatorId`；共享 Chapter 中两人的 `chapterId` 相同。
- `ongoing_contributions`：B 的视角使用 B 的 `creatorId`、A 原 Moment 的 `momentId`；编辑后同一视角内容和 `serverVersion` 更新。
- 照片和语音写入云存储，数据库保留 `cloud://` 文件标识；其他成员通过授权后的临时地址读取。
- 一台手机关闭网络后保存 / 修改，再联网、回到前台，待同步队列应自动减少，另一台手机刷新可见。

不需要删除本机数据来做验收。新设备的内容恢复在本地隔离客户端模拟中已检查，真实设备持久化仍由上述退出重进流程确认。

## 已处理的状态

邀请有效期为七天；既兼容新十二位代码，也兼容旧四十八位代码及旧邀请路径。重复加入显示「已经在这里」，不会重复计人数；失效、目标删除、网络错误、身份变化会给出明确提示。

创建者可在成员页继续复制邀请和移除成员；普通成员只能退出。退出 / 移除后，刷新即失去 Chapter 访问权，已发布的共同内容保留。单独接受过的 Moment 邀请权限独立保留；持有仍有效的 Chapter 邀请仍可再次确认加入。

离线记录与资料修改保留在持久化 pendingOps 中。同步失败不会伪装成成功，也不会通过清空本机数据恢复。邀请必须在目标内容同步到云端后才能生成。

出现错误时，在「我的 → 同步与数据 → 复制诊断信息」查看：
- `CLOUD_UPDATE_REQUIRED`：云函数协议过旧，部署当前 collaboration。
- `DATABASE_COLLECTION_NOT_EXIST`：检查云函数是否部署在建好集合的同一环境。
- `STORAGE_PERMISSION_DENIED`：媒体上传权限未满足。
- `IDENTITY_MISMATCH`：微信账号发生变化，返回并重新进入，原账号缓存会保留。
- `INVITE_INVALID`：请创建者重新生成邀请。

## 本轮验证边界

本地模拟运行的是项目真实的 store、collaboration 和云函数代码，使用隔离缓存、模拟 OPENID 与数据库接口。已通过 Chapter / 单条邀请、文字粘贴解析、双方创建、视角修改、重新进入、离线补传、成员退出、权限和缓存隔离检查。这不等于已连上你的线上数据库完成真机验收。

本轮没有部署远端云函数、上传体验版或登录两个真实微信账号。需要你完成开头两步部署，再按上面两条流程验收；无需跑完整自动化测试。

身份接口依据 [CloudBase 云函数 getWXContext 说明](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)。这里针对当前体验环境已出现的分享限制改用文字邀请，不假定所有小程序都具有相同的分享权限。
